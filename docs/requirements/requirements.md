# 筋トレ合トレマッチングアプリ要件定義書

## 1. プロジェクト概要

### 1.1 背景・課題

筋トレの「孤独」が、各フェーズのトレーニーにとって大きな障壁となっている。

- 【知識と不安の孤独】（初心者）: マシンの使い方がわからず、怪我のリスクや周囲の目が不安。
- 【モチベーションの孤独】（中級者）: メニューがマンネリ化し、一人では限界まで追い込めない。
- 【熱量高みへの孤独】（上級者）: 高重量を扱う際の安全確保（補助）が切実だが、同レベルのパートナーがいない。

### 1.2 解決策と提供価値

本アプリは、単なる「場所のシェア」ではなく、「最適なパートナーとの相互支援環境」をマッチングによって提供する。

| ターゲット | アプリが提供する解決策 | 期待される価値 |
| --- | --- | --- |
| 初心者 | 中級者以上とのマッチング・指導 | 安心感・正しいフォームの習得 |
| 中級者 | 同レベルのパートナーとの合同トレ | サボれない環境・メニューの多様化 |
| 上級者 | 信頼できるスポッター（補助者）の確保 | 限界突破（追い込み）・安全性の向上 |

## 2. 機能要件

### 2.1 プロフィール管理機能

ユーザーの属性と能力を可視化し、ミスマッチを防ぐ。

- 必須項目:
    - ユーザー名
    - 主な活動エリア
- 任意（項目設定）:
    - 筋トレ歴（年・月）
    - 性別
    - 各種記録: ベンチプレス等のMAX重量（マッチングの指標）
    - 目指すカテゴリ（大会勢、ダイエット、健康維持など）

### 2.2 マッチング・検索機能

「いつ・どこで・何を」を軸にしたリアルタイム性の高い検索。

- 検索項目（必須）:
    - 時間帯: いつトレーニングを行うか
- 検索項目（任意）:
    - トレーニング部位（胸、背中、脚など）
    - 重量帯（自分と近いパワーの人を探す）
    - 目指すカテゴリ（熱量の同期）
- マッチングロジック: 募集に対して応募、または相互の「いいね」によるマッチング成立。

### 2.3 コミュニケーション機能

- チャット機能: 合流場所の指定や、当日の服装・メニューの詳細調整。
- 定型文: 初対面でもスムーズに会話を始めるためのテンプレート。

### 2.4 サブ機能（周辺機能）

- ジムマップ表示: 位置情報に基づき、周辺のジムをマップ上にプロット。
- 外部リンク: 各ジムの公式サイトや予約ページへの誘導。

---

## 3. 非機能要件・技術仕様

- プラットフォーム: Webアプリケーション（スマホ利用も想定）
- フロントエンド: Next.js
- バックエンド: Go（Gin）
- データベース：MySQL
- デザイン: モバイルファースト設計、ダークモード対応（ジム内での視認性向上）。
